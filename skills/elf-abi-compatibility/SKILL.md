# ELF 库接口兼容

先确认公开接口与项目承诺、实际旧调用方、新旧工件身份、目标架构、工具链和 ABI 相关选项；共享库、静态库、内联或头文件行为不能用同一检查替代。没有调用方证据不能宣布影响为零。

1. **源码 API：** 比较公开头文件、宏、类型、签名和编译条件；复用旧调用方源码及目标构建。新头文件可编译不说明旧二进制能运行。
2. **二进制 ABI：** 比较可见符号、版本、公开布局、调用约定和相关配置。若只有动态符号，结论限于符号层；有匹配的类型调试信息才依据工具的实际判断报告布局等差异。区分工具错误、发现的差异和信息不足；工具非零不一律解释为破坏性变更。
3. **运行行为：** 保留原始消费者工件；支持时在匹配、隔离且获准的环境用旧工件与新库验证正常、错误及生命周期。不自动替换系统库、运行不可信二进制或发布。
4. **给出迁移或停止条件。** 按公开承诺给出影响范围、分层证据、弃用/迁移和回退建议。单一证据不替代其余两层。

如已有 Libabigail，查 [abidiff 文档](https://sourceware.org/libabigail/manual/abidiff.html) 的输入和返回位标志；按实际版本报告来自何种类型数据。使用其他 ABI 工具时同样记录两边工件身份和覆盖限制。
