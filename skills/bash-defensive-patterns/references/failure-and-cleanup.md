# Bash 失败与清理模式

- 若同一脚本把状态 `1` 同时用于“无匹配”和“失败”，在真实调用位置区分语义；不要用 `|| true` 将所有失败压成成功。
- 若必须获得多段管道的单独状态，在 Bash 覆盖 `PIPESTATUS` 前读取它。需要一段失败即终止时明确采用策略，不把最后一段的状态或全局 `set -e` 当成全部证据。
- 条件调用整个函数（例如 `if 更新函数; then …`）时，不要让函数内部依赖 `errexit` 或 `ERR` trap 终止。关键命令或管道显式返回失败，调用方在验证成功前不提交临时工件。需要检查命令替换时，把声明与赋值拆开，再检查赋值状态；例如不要用 `local value=$(producer)` 接收并判定生产者结果。若替换体包含多条命令，也要核对它是否真的返回了首次失败。
- 消费者按约定只读一部分时，生产者可能因管道提前关闭而退出；例如 Bash 中常见的 `141`。只在已核对消费者输出、提前关闭是约定行为且其他关键段没有失败时，才按预期情况处理，不全局吞掉该状态。
- 退出处理先保留原状态，再仅清理本次独占临时物。若清理失败，记录清理范围，不把它盖过原故障，也不让两种状态都丢失。不要把 dry-run 名称本身当作无副作用证明。
- 对可重复操作，分别核对写入之前、写出部分、完成但后置步骤失败。旧输出仍可用应有实际文件或提交状态的对照。
- 验证关键管道时，至少检查“生产者失败、消费者仍返回零”的对照和最终工件是否保持原样。已有 Bats 等夹具可复用，但断言实际退出和状态，不只检查命令被调用。

版本差异按 [GNU Bash 手册](https://www.gnu.org/software/bash/manual/bash.html)和项目采用的解释器核对。
