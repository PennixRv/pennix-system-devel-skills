# Bash 失败与清理模式

- 若同一脚本把状态 `1` 同时用于“无匹配”和“失败”，在真实调用位置区分语义；不要用 `|| true` 将所有失败压成成功。
- 若必须获得多段管道的单独状态，在 Bash 覆盖 `PIPESTATUS` 前读取它。需要一段失败即终止时明确采用策略，不把最后一段的状态或全局 `set -e` 当成全部证据。
- 退出处理先保留原状态，再仅清理本次独占临时物。若清理失败，记录清理范围，不把它盖过原故障，也不让两种状态都丢失。不要把 dry-run 名称本身当作无副作用证明。
- 对可重复操作，分别核对写入之前、写出部分、完成但后置步骤失败。旧输出仍可用应有实际文件或提交状态的对照。

版本差异按 [GNU Bash 手册](https://www.gnu.org/software/bash/manual/bash.html)和项目采用的解释器核对。
