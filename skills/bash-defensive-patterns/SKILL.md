# Bash 防御式编程

先确认 Bash 版本、启动参数、调用者、外部命令及脚本能改变哪些持久状态。区分代码审查和授权执行；不能把 `bash -x` 或“预览”看成无副作用且可公开。

1. **保持参数边界。** 用数组或带引号的 `"$@"` 传递参数；不要把用户输入拼成命令字符串再解释。检查路径参数的空值、通配、选项和实际命令是否支持 `--`。
2. **从失败点看错误传播。** 对关键步骤明确检查退出状态，区分预期的非零和真正失败。`errexit`、`pipefail`、`nounset` 与 `ERR` trap 有各自条件；按现有测试和执行上下文采用，不全局加严格模式代替检查。
3. **保护输出与清理。** 临时路径只给当前运行使用。先验证结果再替换或提交，保留原始错误，区分中断前后及下次重跑。不要让清理删除调用者已有文件或把部分结果误标为完成。
4. **对照验证。** 正常完成、某一步失败、重跑和不同输入各用目标解释器查证。只报告实际执行过的验证，限制日志输出，不显示凭据、完整环境或可能泄露秘密的追踪。

问题跨管道、条件求值或退出处理时读[失败与清理模式](references/failure-and-cleanup.md)。普通 `/bin/sh` 问题不采用本入口的 Bash 扩展。
