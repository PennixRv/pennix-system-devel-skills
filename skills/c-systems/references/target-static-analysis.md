# 目标静态分析取证

1. **先绑定翻译单元。** 在目标构建产物中找到这次分析实际使用的 `compile_commands.json` 条目，依据 `file`、`directory` 和 `arguments`（或 `command`）核对输入、工作目录及相对头文件路径。同一文件有多个条目或数据库时，确认所选配置、目标与生成来源；宿主目录、目标目录和生成源码不能互相代替。
2. **核对分析器能否读取该配置。** 用实际可调用的工具及版本核对目标三元组、语言版次、宏、`-isystem`、sysroot、强制包含和生成头。对齐检查配置及过滤范围；解析错误、跳过、缺头文件或不支持的编译参数不是“无告警”。在没有实际解析结果时，不声称目标已成功分析。缺工具或目标 SDK 时保留该限制；不能将可运行的宿主分析或手写近似参数报成目标结果。
3. **先做最小对照，再下结论。** 获准执行时，在同一翻译单元上用匹配的目标数据库和明确的检查，比较版本、选中的配置和实际结果；不默认 `--fix` 或批量写回。按实际成功或失败列出覆盖和未运行的分支。零告警不是对象边界证明；已给出的 sanitizer 报告仍按实际运行时证据处理。

报告配置不匹配时，写出“数据库／翻译单元”“编译条目的工作目录（`directory`）”“分析器是否可用且实际解析成功”三项。材料没有给值就标待核对，尤其不要把 `-p` 指向的数据库目录当作条目的工作目录。

字段和工作目录语义见 [LLVM 编译数据库规范](https://clang.llvm.org/docs/JSONCompilationDatabase.html)，工具选项见 [Clang-Tidy](https://clang.llvm.org/extra/clang-tidy/)。
