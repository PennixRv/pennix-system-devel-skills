# 纯 C 系统编程

确认项目使用的 C 版次、编译器选项、可用运行库和平台限制，以头文件、调用方和真正的分配/释放 API 建立契约。不要默认 POSIX、动态分配、异常式错误宏或任何测试框架。

1. **先标对象契约。** 每个指针是借用、独占还是转移所有权？它何时失效，是否允许空值，伴随的长度是字节、元素还是包含终止符？别名、部分重叠或中途重新分配是否改变契约？
2. **先证明边界，再做运算。** 在乘加前检查运算类型、结果类型和业务上限，不能靠事后比较推断没有溢出。核对符号变化、窄化及对齐。数组元素指针的加减限于同一数组及其尾后一位，尾后一位不可解引用；相邻结构体成员不能当作同一数组。分别证明源可读与目的可写的范围。
3. **失败也是接口。** 明确遇到短读、部分初始化或分配失败时输出参数、旧对象和资源的状态。若允许保留原对象，先验证新分配成功再替换；逆向回收仍由本路径拥有的资源，不重复释放或悄悄吞错。
4. **选择最小验证。** 正常、零长度、上界、预期失败和重复清理按目标契约挑选；受限环境无法执行时只报源码证据和待验证条件。性能结论需要给定负载与量测，不因为改成指针写法就认定更快。

输出最小已证实问题或实现建议，并标注所有权、边界和失败后的状态。需要详细规则可按目标 C 版次核对 [SEI CERT C](https://wiki.sei.cmu.edu/confluence/display/c/SEI+CERT+C+Coding+Standard)；目标工程的 API 和编译条件优先。
