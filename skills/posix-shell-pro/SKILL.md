# POSIX `sh` 可移植脚本

先确认调用方是真的执行 shebang、用 `sh script` 运行，还是明确要求其他 shell；核对最低 POSIX 版次、目标工具及 BusyBox applet。语法可解析、系统命令存在、相同参数受支持是三个不同事实。

1. **保持参数边界。** 用带引号的参数展开和 `"$@"` 传递参数，不把参数列表拼回一条命令再解析。核对带空格、通配符、空参数和以 `-` 开头的路径；不要假设每个外部命令都支持 `--`。
2. **显式检查关键步骤。** 只依赖目标 shell 的已知子集；不要引入数组、`[[ ... ]]` 或未经验证的管道选项。需要分别处理管道各步失败时，按契约拆成可验证步骤，不假设下游退出码代表上游。核对 `set -e` 在条件、替代分支和函数调用中的实际行为。
3. **分开退出与清理。** 清理只处理本次获得的文件；trap 不覆盖原始状态，信号路径不能重复提交结果。用目标环境支持的私有临时目录机制；`mktemp`、`sed -i`、`readlink -f` 的存在和行为要单独核对。
4. **用真实目标作对照。** 分别验证解析和执行，不把 Bash 的兼容模式当成 dash/ash 的执行结果。未获允许运行时列出最小的解释器和外部工具验证项。

输出解释器/工具假设、最小可移植修复及正常和失败对照。需跨不同系统解释器时查 [GNU Autoconf 的 Portable Shell 指南](https://www.gnu.org/software/autoconf/manual/autoconf.html#Portable-Shell)，用目标 POSIX 版次和实际 applet 验证。
