# C++ 测试

先查实际 CMake preset、构建目录、测试目标和项目采用的 GoogleTest 版本。遵循现有测试框架与测试命名，不因一个用例改依赖、语言标准或项目最低 CMake 版本。

1. **按行为固定对照。** 复用现有测试文件建议最小失败回归；用 fixture 管独立且必要的状态，只 mock 真正跨过的不可控边界。检查共享状态、时钟、错误先后和对照输入；断言应验证外部可见行为而不是复制生产分支。
2. **辨认注册和发现方式。** 查实际 CMake 声明与 CTest 记录。`gtest_add_tests()` 从源码识别用例，`gtest_discover_tests()` 则查询测试程序；自有入口按其实现核对。使用后者时检查发现是在构建后还是测试前，以及该目标是否配置匹配的执行器。分别记录编译、发现和执行，不由其中一项推出另一项。
3. **按项目入口验证。** 选实际测试目标和构建目录。用户已授权执行且工具齐备时，运行最小相关测试；否则给出命令建议和缺项。宿主替代测试可提供补充证据，但不能冒充目标运行。不默认更改构建或下载依赖。
4. **核对检出价值。** 对正常、边界、故障与清理各给必要断言；被测行为确定时不靠重复重试判定。当前项目已有 sanitizer、覆盖率或故障注入才按任务使用。

涉及进程、资源和持久状态失败时读[失败路径对照](references/failure-paths.md)。交叉发现选项按目标 CMake 版本查 [GoogleTest 模块](https://cmake.org/cmake/help/latest/module/GoogleTest.html)。
