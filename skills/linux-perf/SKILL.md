# Linux `perf` 性能取证

先确认工作负载、时间窗口、目标进程或 CPU 范围、CPU/内核、工具事件及符号身份。不要默认获取额外权限；事件不可用、采样不充分和符号缺失都是证据限制。

1. **计数回答规模问题。** 区分实际读数、事件未支持、没有计数和权限失败。按同一事件、范围和有效工作定义比较；复用时检查运行／启用占比及缩放，不能把估计当全窗口精确读数。
2. **采样回答在哪里。** 核对目标事件、样本范围、丢样、调用链与符号匹配。自身与含子调用占比含义不同；热点只说明已采事件的分布，不直接证明耗时比例或根因。需要判断数据可靠性时读[性能证据边界](references/evidence.md)。
3. **只补能区分解释的证据。** 保留现场匹配的工件；没有可比数据不报改善幅度。未获准采样只建议最小范围和事件，不默认采全系统、启动负载或修改系统权限。

输出数据条件、可靠的热点或计数观察、不能推出的结论和最小下一步；不要将未证明的微架构判断写成事实。
