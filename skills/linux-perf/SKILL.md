# Linux `perf` 性能取证

先确认工作负载、时间窗口、目标进程或 CPU 范围、CPU/内核、工具事件及符号身份。不要默认获取额外权限；事件不可用、采样不充分和符号缺失都是证据限制。

1. **计数回答规模问题。** `perf stat` 适合比较相同工作负载下的计数；先确认事件定义、线程范围、持续时间、复用和可比性。不同事件或未完成的数据不能直接并排得出退化比例。
2. **采样回答在哪里。** 解释 `perf record`/`perf report` 的目标事件、样本来源、调用链与符号匹配；热点是定位线索，不等于根因。需要展开时读[性能证据边界](references/evidence.md)。
3. **只验证最有区分力的假设。** 根据现有结果选择一个可复核的下一步，对照同负载、同目标和同类事件。无现成证据且未获准采样时只给测量方案；不默认采全系统、启动负载或修改系统权限。

输出数据条件、可靠的热点或计数观察、不能推出的结论和最小下一步；不要将未证明的微架构判断写成事实。
