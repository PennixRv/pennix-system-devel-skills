# C++ 实现与审查

先核对实际目标的语言版次、编译和链接选项、库实现以及项目的异常、RTTI、分配和线程政策。依据改变的调用边界或资源提出具体判断，不统一改风格，也不将更高标准的语法或库视为已可用。

1. **先追对象寿命。** 对引用、指针、迭代器和借用视图，找到存储的所有者及其失效条件：临时对象析构、容器变更、对象移动后原契约改变，或异步回调跨越调用期限。临时对象是否延寿取决于引用的初始化方式和适用例外，不凭 `const` 判断；`std::string_view` 不拥有所指内容。借用可能失效时，比较拥有数据与缩短借用期限的代价。
2. **让接口表达实际责任。** 区分可空借用、不可空借用、独占和真实共享。避免为了表达借用而引入不必要的共享所有权或堆分配；已有 C 接口、固定容量或跨二进制边界时，以目标工程的内存和兼容合同为准。
3. **推导正常与异常状态。** 核对初始化是否完成、失败是否保留旧状态、移交后谁清理、析构路径是否可能出现其他错误。禁用异常时使用已有状态或错误类型并检查调用方传播，不引入 `throw` 或更改全局编译选项。
4. **核对值域与并发。** 比较转换前后的范围、单位和端点；同步覆盖真实共享对象及最后访问，不能因使用智能指针或 `const` 推断线程安全。用实际操作间的顺序及对象发布／回收说明原子同步，不把某条 CPU 指令或另一个语言的内存模型当成 C++ 保证。删减锁、移动对象或改变布局的性能主张需要证据。

输出与实际差异有关的发现、受影响调用方、最小变更和可验证对照。不要把另一语言标准下编译成功当成项目通过。公开的 [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)可作为外部阅读，不覆盖项目合同，也不是本 Skill 的规则清单。
