# 交叉工具链取证

把编译/链接发生的机器、构建过程中运行的工具、最终工件运行的机器分开。用真实命令、编译器版本及目标、sysroot、链接输入和现成工件核对，不靠工具名前缀、环境变量或另一次构建猜测。

1. **分类第一处异常。** 找不到头文件、库不可解析、ELF 架构不匹配、动态解释器找不到是不同层。核对编译搜索路径、链接器实际选中的文件、目标工件头与运行环境；不要为一个类误差默认调整 CPU flags、强制链接或关闭检查。
2. **区分目标依赖和宿主工具。** 生成代码的工具可能正确运行在宿主，目标依赖则必须满足目标 ABI。查 `pkg-config` 的目标 `.pc` 搜索目录与 sysroot 重写；单独设置 sysroot 不能证明不会读到宿主 `.pc`。现有 CMake、Meson 或 SDK 配置见[平台配置取证](references/build-context.md)。
3. **逐层说明证据。** 分开报告编译、链接、ELF 身份与实际运行。若构建已通过就先根据日志和已有工件解释，不自动装工具链、启动 QEMU、加载 SDK 或重配。

输出真实使用的工具链、冲突路径、最小建议和下一项证据；对裸机或非 ELF 目标，按实际对象格式和运行环境调整检查，不能套用 Linux 解释器约定。
