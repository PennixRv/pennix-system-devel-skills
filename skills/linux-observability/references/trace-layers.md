# 追踪层和采集边界

| 需要的判断 | 优先检查 | 不能据此得出的结论 |
| --- | --- | --- |
| 哪次调用返回了具体错误，等待发生在哪一侧 | 现有 syscall 记录中的进程、线程、参数边界、返回值和运行范围；用户态库调用另核采集器对目标的覆盖 | 看见 syscall 不能证明其上层业务调用原因；缺一条记录并不证明没执行 |
| 某个内核事件先于另一已知事件 | 目标内核的 tracepoint/现有记录格式、时间域、采样和丢失；只有必要时才考虑该构建可用的动态探针 | BTF 或动态探针可用不等于事件字段和跨版本语义相同，也不等于获准挂载 |
| 应用层端到端或跨线程等待 | 同请求键、同语义的开始/结束、事件生产者与消费者、时钟转换；离线查询先验证少量原始行与汇总相符 | 不用不能映射的线程号或墙钟猜顺序；单条事件不能定性总体尾延迟 |

需要解释查询和事件格式时对照 [Perfetto Trace Processor](https://perfetto.dev/docs/analysis/trace-processor)、[Linux libbpf 概览](https://docs.kernel.org/bpf/libbpf/libbpf_overview.html)或目标版本的 [bpftrace 文档](https://bpftrace.org/docs/)。先明确哪些数据从哪里来、哪些字段不该采、何时停止；不默认调整内核权限或扩大作用域。
