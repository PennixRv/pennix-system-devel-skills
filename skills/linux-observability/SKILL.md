# Linux 事件追踪

先问追踪要证实哪条顺序或关系，优先用已有数据，不从工具名推断采集层。系统调用、用户态库调用、内核事件与业务采集点观察的边界不同；不同来源都看见同一名称也不能直接关联。

已有时间线只是延迟分解或优化比较的输入时，`systems-performance` 可直接判读；仅在需要核对采集来源能否关联、解释追踪字段或具体设计采集点时补充本入口。

1. **把事件放到同一证据范围。** 核对进程、线程、请求或对象代次，时钟域、对时锚点、采集起止、过滤及丢失计数。关联标识未证实时不能拼接；不同时钟无转换证据不能直接相减。未见事件可能是过滤、丢失或未采集，不等于事件未发生。
2. **区分观察和推断。** 事件先后不自动说明因果。只指出已成立的顺序和待证假设，保留原始时间口径。现有时间线不能回答时，选能区分解释的最少采集点、关联键和对照窗口，并说明探针负担、敏感字段及什么结果才算有效。
3. **按目标和授权选工具。** 有记录先离线分析；按需要区分 syscall／事件／应用追踪，不因 eBPF 或某个工具可用就更换采集。版本、权限、时钟和目标范围未证实时给出缺项，不默认附加、提升权限、装载探针或发送日志。

输出是否可关联、已知与未知顺序、下一项足以区分假设的证据。若需要写查询或选择事件，读[追踪层和采集边界](references/trace-layers.md)。
