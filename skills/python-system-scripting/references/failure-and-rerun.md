# 失败与重跑的最小对照

按状态变化固定故障位置，不要求采用某个框架。使用现有隔离夹具、替身程序或测试依赖，不在用户数据上注入失败。

| 失败位置 | 保存的观察量 |
| --- | --- |
| 进程未启动 | 错误类型、不会被覆盖的原有工件、是否曾生成临时文件 |
| 已启动但未完成 | 直接子进程和实际写者是否结束；失效的临时工件不能被消费 |
| 已有字节但验证失败 | 旧版本仍可用；输出目录没有误认成最终版本的产物 |
| 提交后通知失败 | 重跑能识别新版本已完成，不重复危险操作；如果无可验证标记，报告不确定 |

SQLite 的[测试策略](https://sqlite.org/testing.html)是按明确故障点核对持久状态的先例，不要求脚本使用 SQLite。若项目没有断电测试，不把进程终止测试当成断电结论。

若风险是后代继承输出管道或继续写入，验证不能只断言捕获 `TimeoutExpired`。在隔离夹具中分别断言直接子进程已回收、实际写者不再写、旧工件未损坏和后续运行能否安全恢复。
