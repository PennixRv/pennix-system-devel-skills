# Python 系统脚本

先明确运行解释器、可执行文件、参数来源、工作目录与必要环境、允许修改的状态，以及负责处理失败现场的角色。优先沿目标项目已使用的入口，不默认启动 shell、访问真实环境或执行命令重现日志。

1. **核对调用合同。** 在不需要 shell 语义时传独立参数；把命令的失败启动、不可接受的退出码、超时与输出解析失败分开。以外部程序定义的退出码和工件约定为准，不把空标准输出、零退出或异常捕获本身当成操作成功。
2. **明确超时的处理范围。** 查实际使用的 `subprocess.run` 或 `Popen` 接口。超时后确认直接子进程是否终止和已回收；如果还有后代、管道或并行写者，单独核对其生命周期。不假设终止一个 PID 解除了所有写入；不要未经授权向共享进程组发送信号。
3. **标出成功提交点。** 中间工件由本次运行所有；验证完整性后才将新结果对外可见。在设计允许用同文件系统替换时，写入私有中间文件，验证后通过项目允许的方式提交；原子替换不等于断电后可恢复，也不能使多个文件一起原子更新。共享目标还要检查并发与旧状态是否允许覆盖。
4. **对比失败前后。** 用现有夹具测试启动失败、执行中超时、写到一半崩溃、提交前失败及重跑。保留原始错误；清理只能处理可证明属于本次运行的临时物。摘要报告外部程序与出错步骤，不回显秘密参数、环境或完整输出。

输出：参数和退出约定、超时的实际回收范围、工件及重跑边界、未执行检查。需要设计故障对照时读[失败与重跑](references/failure-and-rerun.md)；接口行为对照目标 Python 版本的 [`subprocess` 文档](https://docs.python.org/3/library/subprocess.html)。
