# 裸机启动与镜像布局

先确认芯片、修订、启动方式、目标 ABI、启动器和实际工件。先区分 ROM 或上一级启动器没有交接、CPU 未进入目标入口、初始化段错误以及应用入口之后的问题；不要假定目标一定采用某种向量表或地址。

1. **把复位路径和责任对起来。** 按目标实际约定核对入口、初始栈、向量/异常处理和早期硬件状态；确认谁会设置 RAM、栈、时钟以及 C/C++ 运行时。只在该阶段必要且有目标证据时分析。
2. **对比运行地址和装载地址。** 用 map、ELF 段/符号与实发镜像工具链核对 `.data` 拷贝源/目的、`.bss` 清零范围和保留区；确认脚本输出符号与启动代码引用一致。检查镜像头、偏移、对齐和向量等是否满足目标约定，不能只靠 ELF 入口值推断实发镜像。
3. **给出适用的验证证据。** 静态差异说明布局假设，不证明设备已启动。若已有模型日志，只验证模型明确包含的启动步骤和外设；需要时向所有者说明缺少的板级证据，未授权不接探针、复位、刷写或改 Image/bootloader。

输出最早可定位的启动阶段、相关工件和最小修正或验证。GNU 工具链可按目标版本核对 [链接器脚本手册](https://sourceware.org/binutils/docs/ld/Scripts.html)，芯片细节按目标手册和勘误。
