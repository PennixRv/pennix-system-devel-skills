# Linux 驱动生命周期

从目标内核树确认版本和子系统、总线驱动的真实回调、内建还是模块、设备如何出现。示例、其他版本的接口和另一个板卡的配置不能替代这些证据。仅追查 `CONFIG_*` 时，直接读 [Linux Kconfig 值追踪](references/kconfig-values.md)，不要求修改驱动。

1. **列资源和发布时点。** 区分获取、初始化、对外可见、停止使用、释放。记录 IRQ、DMA、定时器、工作队列、设备引用等实际存在的使用者；找出初始化未完成时是否已有消费者可以进入。按当前子系统契约处理失败和延迟探测，不从一个示例推断所有驱动都使用相同回调签名。
2. **逐个核对部分失败。** 对每个可能失败的阶段，说明已经获取或对外发布的资源、回退责任，以及之后是否可能重试。区分手工生命周期和受管资源；不重复释放，也不能因为使用 `devm_*` 就跳过异步停机。
3. **先禁止新的访问，再同步在途访问。** 按目标 IRQ、工作队列和子系统约定关掉生产者并等待正在执行的路径，再撤销它们依赖的资源。考虑工作会重新排队、回调间接访问数据及持锁等待死锁；不把“取消已请求”当成“最后访问结束”。失败回退与正常解绑都要满足此顺序。
4. **按当前树取证。** 把调用路径、配置符号、构建目标和已知工件关联起来；标明证据来自源码、现成构建输出、模拟还是硬件。缺目标树或平台条件就列出最小缺项。不默认重配、构建、加载模块、绑定设备或改宿主内核。

输出以资源与使用者的顺序、具体缺口、建议变更及最小验证收尾。权威依据用目标分支的 [Linux Driver API](https://docs.kernel.org/driver-api/)、[Devres](https://docs.kernel.org/driver-api/driver-model/devres.html) 与 [Kbuild](https://docs.kernel.org/kbuild/)；公开文档不能替代目标树。
