# GNU Make

确认方言、实际目录、顶层和被包含的 Makefile、传入变量及目标。生成的 Makefile 是现场证据，修复应回到生成器输入。make 的配方由实际 `SHELL` 解释，不能从 GNU Make 推断一定有 Bash。

1. **定位目标和依赖边。** 追默认目标、`.PHONY`、规则 stem 和 `$@`／`$<`／`$^` 的实际含义。目录等必须先存在但不改变产物内容的输入适合顺序依赖；头文件、配置和生成内容不能为了少重建而误用顺序依赖。
2. **追踪受影响对象的依赖文件。** 已有 GCC/Clang 依赖生成时，核对 `.d` 的产生位置、目标名、包含位置及生成头文件的生产者。漏重建先证明缺边；总重建先确认哪条依赖或输入在变化，不用 `clean` 或强制重建掩盖问题。
3. **核对实际命令与递归。** 区分编译标志、链接选项和库次序，确认外部覆盖是否仍有效。并行错误优先找缺边或共享中间物，不默认关闭并行。`make -n` 不能当成不执行保证；先看规则和已知副作用，需要跑时按目标授权限制。

给出具体规则、依赖关系、最小修复和验证对照，例如只改头文件或只改目录时间时的预期差异。变量与依赖语义查 [GNU Make 手册](https://www.gnu.org/software/make/manual/)。
