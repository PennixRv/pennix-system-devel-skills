# Linux io_uring

先固定实际内核、liburing 版本、操作类别、运行环境和确认可用的功能。已有环的事件日志优先；评估选型时先核对必须支持的内核与负载、退化路径，以及是否确实需要替换已有接口。

1. **说清所有权和代次。** 记录用户态队列、已提交请求及最终完成如何关联；不要把环上的槽与应用资源寿命等同。按该操作核对缓冲区和文件引用由谁持有、何时归还；复用标识要能区分在途请求。使用多次完成或注册缓冲时核对各自终态及该代次仍活跃的条件。
2. **把取消与原完成分开。** 取消有自己的完成事件；`-ENOENT` 或 `-EALREADY` 都不证明原请求已被消费。收割实际原请求终态或核对该操作的明确排空契约后再释放；处理完成与取消交错、部分 I/O、晚到结果和关闭中不再提交的边界。
3. **限制在途及回退。** 用有界的在途请求量和可观测拒绝/等待策略避免内存无限增长，核对提交不足、满队列和消费方滞后。只在实际目标支持且有授权时验证；不默认调整 seccomp、内核开关、设备绑定或引入 AF_XDP/DPDK。

输出请求状态转移、资源释放点、失败或过载行为与验证条件。取消语义查对应版本 [liburing 手册](https://github.com/axboe/liburing/blob/master/man/io_uring_prep_cancel.3)，不要用另一个版本或操作的示例替代目标证据。
