# Linux 用户态系统软件开发

从目标代码、测试与实际启动方式确认进程管理者、事件循环或线程模型、回调可能在哪个上下文执行，以及哪些状态可被调用方观察。不默认项目采用 libuv、systemd、特定事件循环或固定的退出协议。

1. **定义就绪。** 列出接口可对外服务前必要的资源、初始化和失败回退。区分进程已启动、监听端点已建立、服务能正确处理请求；以调用方或服务管理器实际观察的信号为准。就绪前失败不得留下能误导重启或下一进程的状态。
2. **追踪实际所有者。** 对关键文件描述符、连接、定时器和异步回调，明确获取者、可能使用者、最后一次使用、关闭责任与线程边界。注册失败和部分初始化也走同一所有权判断；不能因为另一线程发出取消请求，就假设回调已经结束。
3. **定义停止期间还接受哪些工作。** 区分新的外部请求与在途请求完成所需的内部回调；按项目契约决定排空还是取消。若有关闭期限，说明超时后状态和关闭责任。确认回调或线程已完成最后一次访问再释放，避免停掉完成路径后仍等待它。
4. **核对失败证据。** 优先使用已有日志、线程记录、目标代码和测试。退出挂起时，把等待者、解除等待的事件和仍能处理该事件的线程或循环连起来；若等待者也是唯一能处理完成事件的一方，先核对完成顺序，不靠加大超时掩盖。区分检测到错误、完成回退、进程退出、下一次正常启动。未经授权不启动、附加或重载真实服务。

输出：可观察状态、所有权和关闭顺序、具体风险或最小修改、已有证据与待验证项。涉及事件循环和服务管理器时，按目标项目版本对照 [libuv 设计](https://docs.libuv.org/en/v1.x/design.html) 的句柄生存期，或 [systemd 就绪通知](https://www.freedesktop.org/software/systemd/man/latest/sd_notify.html) 的通知条件；只采用目标工程需要的部分。
