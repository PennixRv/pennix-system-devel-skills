# Linux 内核变更审查

先确认评审基线、真实差异、目标树及适用架构和配置。若只给源码片段且无法确定这是行为变更，说明限制，不称其为回归。不要修改文件、发布评论或要求预处理工作树；有可用索引时结合当前源码核对，没有索引时用有界导航。

1. **按改动口径缩小证据。** 确认子系统、接口消费者和改变的行为；对照树内同类实现、文档、Kconfig 与编译条件。需要时读[子系统取证](references/subsystem-evidence.md)，不要逐个遍历无关子系统。
2. **把怀疑写成可验证的因果链。** 对每个候选问题比对旧、新行为，确认入口可达、资源或状态有效、权限和执行上下文具备，指出触发条件、最后相关使用及可观察后果。对锁、IRQ、工作队列和发布/销毁次序，需要读到实际调用方。
3. **主动找反例。** 检查是否有上游锁、同步或失败回退消除风险；配置是否排除了该路径；问题是否原已存在。未证明的猜测写成验证缺项，不作为已证实发现。测试、构建与设计结论分别报告，不自动构建或加载内核。

输出按影响排序：文件与行、证据链、触发条件、后果和最小修正方向；无明确问题时说明评审范围与未验证项。测试建议先复用该子系统已有入口。
