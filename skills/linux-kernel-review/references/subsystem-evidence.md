# 按子系统定位证据

从目标树 `MAINTAINERS`、相关文档、同目录实现和调用方开始，不把外部参考树当成当前代码。

| 改动 | 核对真正起作用的证据 |
| --- | --- |
| 工作队列、定时器、IRQ | 谁还能安排新工作、何时完成最后一次使用、同步点和锁依赖。 |
| 驱动与电源管理 | 哪些失败路径已使资源可达，停止生产者与释放的顺序，运行时和系统休眠适用条件。 |
| Kbuild / Kconfig 和架构选择 | 声明、实际构建规则、架构依赖、最终配置、内建/模块差异。没有目标配置时区分确定和条件性问题。 |
| UAPI、sysfs、netlink | 公开结构布局、输入与错误返回、旧调用方及相应兼容路径。 |

树内单元逻辑优先寻找 KUnit，内核对用户态的行为优先找子系统实际使用的 kselftest，系统级回归可对照 LTP 的既有能力。只报已运行的入口和环境；不要默认向真实宿主注入故障。参见 [Linux 测试概览](https://docs.kernel.org/dev-tools/testing-overview.html)。
