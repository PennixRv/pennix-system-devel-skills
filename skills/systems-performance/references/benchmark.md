# 性能基准与复测

- **固定比较对象。** 记录工件、构建参数、输入规模与分布、到达率或并发方式、环境和起止点。微基准分开计量准备、目标工作、消费结果与清理；确认编译器没有删掉需测的工作。既想隔离一个操作又关心端到端收益时，分别保留两种结果，不用前者替代后者。
- **以约束定义成功。** 用项目已有预算决定观察有效吞吐、端到端时延及尾部、错误／超时／丢弃、峰值资源等必要指标。批处理比较应从单个任务进入到可以观察到完成，含成批等待；低负载和满负载可得不同结论，不混用分母。服务慢时要核对负载发生器是否随被测系统减速、漏记未及时发出的任务，不用成功请求的漂亮分位数掩盖失败。
- **控制扰动，不改问题。** 可行时配对重复或交错顺序，说明冷启动与预热、缓存和并发条件，保留每轮样本和失败。频率、后台负载或输入变化可能主导差异；可以记为限制，不默认改 governor 或清宿主缓存。样本不足、差异接近波动或长尾未被覆盖时报告“未证实”，不挑有利轮次或平均各轮分位数冒充总体分位数。
- **用等价运行验证接受条件。** 与首轮同口径，核对正确性、顺序、错误与重试语义，比较不允许退化的门槛。记录绝对值、单位、条件和不确定性，再给相对差异；负载或定义不可比时不报百分比。仪器有明显开销时，将用于定位的观测与用于验收的复测分开。

已有工具足够时不引入新框架。可按实际测量边界参考 [Google Benchmark](https://google.github.io/benchmark/user_guide.html)、[pyperf](https://pyperf.readthedocs.io/en/latest/run_benchmark.html)、[hyperfine](https://github.com/sharkdp/hyperfine) 和 [wrk2 的尾延迟测量说明](https://github.com/giltene/wrk2)。
