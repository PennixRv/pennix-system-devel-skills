# 系统软件性能分析与优化

先确认要改善的指标、工作负载、测量边界和不可退化的约束。快的是单次计算、请求完成，还是单位时间的有效产出？延迟、正确性、错误率和资源上限按目标工程约定，不用通用阈值代替。

1. **比较前固定同一问题。** 明确有效工作、起止点、同等输出与失败语义，使用实际可得到的重复对照。仅有单次或条件不一致的结果时，只作观察；设计对照、评估噪声或复核收益时读[基准与复测](references/benchmark.md)。
2. **归因需要能区分解释的证据。** 先分解运行、可运行但未获调度、阻塞以及应用的排队边界；只挑最有区分力的一项补证。解释 Linux 等待、资源或时序时读[Linux 瓶颈证据](references/linux-evidence.md)，不因指标名就默认选工具。
3. **先改已知成本，再核对副作用。** 优先减掉可证实的工作；涉及热路径、并发或脚本分层时读[热点优化](references/hot-paths.md)。复测时同时核对原指标与不可退化项；吞吐改善不能抵消超出已约定的尾延迟或错误预算。

输出可确认的观察、仍可能的解释、最小下一步及接受或停止条件。证据足以回答时不追加采集；无授权时给方案，不启动负载、附加进程、扩大全系统观测或改系统设置。
