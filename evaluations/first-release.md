# 首发行为评测基线

用合成夹具，不用真实项目源码、凭据或运行环境。A 与 B 使用相同的两套既有集合完整成员、宿主、模型设置、项目指令和请求；只有 B 可见候选成员。隔离的不只是 `CODEX_HOME`：两个试验环境都不能读到评测仓库、判据、其他试验环境或真实用户目录。只把渲染后的请求与证据送入新会话；不让被测会话自行调用本仓库脚本生成提示。

记录实际宿主、模型、源提交、成员树和渲染输入摘要。先做一个配对检查轨迹：实际完成的读取应能对应到已固定成员或参考的路径和返回内容；工具参数、路径列表、失败的命令、模型自述均不算读到。若路径或返回内容无法从原生轨迹判明，标记未知，先停止扩大样本。审查者按分开的读取事实、工程判断、缺项和越权动作验收，不按关键词给分。原始轨迹只在隔离外的受控位置保存，不进入 Git。

[`cases.json`](cases.json) 是逐例输入与判据的唯一来源。`python3 -B evaluations/case.py` 列出用例，`python3 -B evaluations/case.py <ID>` 生成提示，`python3 -B evaluations/case.py --rubric <ID>` 仅供审查者查看判据。这些命令不发起模型请求。

- **正例：** 检查预期主入口、必要时实际读取的参考和对题目的具体帮助。有 A 对照时另外记录 B 提供的可复核增益或没有增益；没有 A 对照不能声称该用例证明了相对增益。
- **对照：** `covers` 表示本例考察的条目，不表示必须加载或必须不加载。例如纯 C 不使用 C++ 入口；顺序依赖正确时仍可使用 GNU Make 入口，但不能捏造缺边；只查 Linux `CONFIG_*` 值时仍可查驱动条目的 Kconfig 参考。以逐例判据区分路由、误报、越权和证据外推。
- **混合任务：** 按用户需要的结论选入口。Yocto 内核片段未生效先核对所选配方及 append；Zephyr 工件的 GDB 符号错配先核对调试工件。出现平台、语言或工具名不等于需要第二个入口；只有第一份证据留下独立问题时才补读。
- **迁移对照：** 换项目布局或入口后复查同一判断，不要求照搬旧项目的环境、框架或工具。带“已授权”的假设题只检验是否能给出匹配的验证建议，不证明实际执行能力。
